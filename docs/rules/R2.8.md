# R2.8: No unsafe code or HTML sinks

**Short answer:** Eval or exec on a non-literal, new Function, unsanitised dangerouslySetInnerHTML, interpolated SQL strings and hidden control characters. Code or HTML built from a string runs whatever the string holds; with any outside input in it, that is an injection.

Group: Security and tenancy. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

No unsafe code or HTML sinks: eval or exec on a non-literal, new Function, unsanitised dangerouslySetInnerHTML, interpolated SQL strings and hidden control characters.

## Why

Code or HTML built from a string runs whatever the string holds; with any outside input in it, that is an injection.

## A bad example

```ts
eval(userInput);
```

## A good example

```ts
const value = JSON.parse(userInput);
```

The fix depends on the finding and the language:

- SQL built from a string in Python: `cur.execute("SELECT * FROM users WHERE name = %s", (name,))`
- SQL built from a string in TypeScript and JavaScript: `await db.query('SELECT * FROM users WHERE name = $1', [name]);`
- HTML set from a string in TypeScript and JavaScript: `<div>{text}</div>`
- code run from a string in TypeScript and JavaScript: `const value = JSON.parse(userInput);`

## How it is checked

- What it reads: JavaScript and TypeScript (.ts, .tsx, .js, .jsx, .mjs, .cjs): eval, new Function and, in .tsx and .jsx, dangerouslySetInnerHTML. Python: eval and exec on a non-literal. Python and JavaScript and TypeScript: SQL built by string interpolation. Any code file: hidden control characters.
- `brevio-core scan` checks the lines you add for it.

## Measured precision

100% of 20 judged hits were real, on human-written code, one reviewer (corpus ts-react-oss, run on 2026-11-06). That is not how often the rule is right on code an agent wrote. See `docs/precision.md` in the brevio-core repository for the verdicts, the commands to run it again and how to dispute one. The Python checks of this rule were added after this run, so they are not measured.

## How to silence it

A person can silence one finding with `brevio-core: ignore R2.8 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

What the scanner already leaves alone: Comment lines and Playwright's $eval and $$eval are not flagged; dangerouslySetInnerHTML is checked only in .tsx and .jsx files outside tests. In Python, `model.eval()`, `ast.literal_eval` and eval or exec of a plain string literal are not flagged.

A scan reads only the lines you add, so a line that was already in the file is not flagged.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
