# R20.1: Existing test files kept

**Short answer:** A test file on the base is not deleted or renamed to a file that is no test. A test file that is deleted, or renamed so that a runner no longer collects it, stops guarding what it covered. Sometimes that is right, for example when the code it tested is gone, so a person looks.

A finding is a prompt for a reviewer, not proof of a problem: a change can drop or rewrite a test for a good reason. `brevio-core scan` does not run this rule, so no scan fails on it. `brevio-core check` reports it and exits 1 when it does. ## What it catches

Existing test files kept: a test file on the base is not deleted or renamed to a file that is no test.

## Why

A test file that is deleted, or renamed so that a runner no longer collects it, stops guarding what it covered. Sometimes that is right, for example when the code it tested is gone, so a person looks.

## A bad example

```
git rm tests/test_billing.py   # the change that made it fail stays in
```

## A good example

```
restore the test file and fix the code it tests
```

## How it is checked

- `brevio-core check` compares the working tree with `--base` (default `HEAD`). The agent hook runs the same comparison when the agent stops, and `brevio-core patch` runs it on an edit before writing it. `brevio-core scan` does not run it.

## Measured precision

Not measured. No judged sample of this rule's hits exists.

## How to silence it

An ignore comment does not silence this rule: `brevio-core check` does not read one for it, and a setting in `brevio-core.toml` does not turn it off. A person who means the change keeps it for a reviewer to accept; an agent restores the test.

What the check already leaves alone: only Python files named test_*.py or *_test.py, and JavaScript or TypeScript files named *.test.* or *.spec.*, count as test files.

To change what the rule flags, edit its check in `gates/core_gates.py`. That is a code change and is reviewed like one.
