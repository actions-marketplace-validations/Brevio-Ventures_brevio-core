# R2.6: Constant-time secret comparison

**Short answer:** Use timingSafeEqual / compare_digest. A normal string compare stops at the first wrong byte, so timing leaks the secret.

Group: Security and tenancy. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Constant-time secret comparison: use timingSafeEqual / compare_digest.

## Why

A normal string compare stops at the first wrong byte, so timing leaks the secret.

## A bad example

```ts
if (token === expected) ok();
```

## A good example

```ts
if (timingSafeEqual(Buffer.from(token), Buffer.from(expected))) ok();
```

## How it is checked

- `brevio-core brief` and the `brief` tool of `brevio-core mcp` print a one-line reminder of it for a file that matches.

## How to silence it

A person can silence one finding with `brevio-core: ignore R2.6 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
