# R11.3: Race condition prevention

**Short answer:** UI mutations abort pending conflicting requests via AbortController. A slow first request can overwrite the result of a newer one.

Group: State and concurrency. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Race condition prevention: UI mutations abort pending conflicting requests via AbortController.

## Why

A slow first request can overwrite the result of a newer one.

## A bad example

```ts
fetch(url).then(setData);
```

## A good example

```ts
ctrl.abort(); ctrl = new AbortController();
fetch(url, { signal: ctrl.signal }).then(setData);
```

## How to silence it

A person can silence one finding with `brevio-core: ignore R11.3 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
