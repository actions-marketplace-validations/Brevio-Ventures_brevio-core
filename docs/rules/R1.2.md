# R1.2: SSR visibility resilience

**Short answer:** Leave no [data-reveal] at opacity:0 without a CSS animation fallback. If scripts load late, an element that starts at opacity 0 stays invisible for the visitor.

Group: UI and mobile performance. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

SSR visibility resilience: leave no [data-reveal] at opacity:0 without a CSS animation fallback.

## Why

If scripts load late, an element that starts at opacity 0 stays invisible for the visitor.

## A bad example

```css
[data-reveal] { opacity: 0; }
```

## A good example

```css
[data-reveal] { opacity: 0; animation: show 0s 1s forwards; }
@keyframes show { to { opacity: 1; } }
```

## How it is checked

- `brevio-core scan --surface` checks the lines you add for it; a plain `brevio-core scan` does not.
- `brevio-core brief` and the `brief` tool of `brevio-core mcp` print a one-line reminder of it for a file that matches.

Not measured. No judged sample of this rule's hits exists.

## How to silence it

A person can silence one finding with `brevio-core: ignore R1.2 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

What the scanner already leaves alone: A file that holds a @keyframes block is not flagged.

A scan reads only the lines you add, so a line that was already in the file is not flagged.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
