# R16.3: Scoped internal packages

**Short answer:** Monorepo internal packages use scoped organization prefixes. An unscoped internal name can be taken by someone on the public registry.

Group: Supply chain. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Scoped internal packages: monorepo internal packages use scoped organization prefixes.

## Why

An unscoped internal name can be taken by someone on the public registry.

## A bad example

```json
"name": "billing-utils"
```

## A good example

```json
"name": "@acme/billing-utils"
```

- Nothing yet. No `brevio-core` command checks it and no `brief` reminder names it: it is a standing rule for authors and reviewers.

## How to silence it

A person can silence one finding with `brevio-core: ignore R16.3 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
