# R10.3: Rate-limit header handling

**Short answer:** Parse 429 Retry-After and respect backoff deadlines. Ignoring Retry-After keeps you rate limited for longer.

Group: API and network robustness. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Rate-limit header handling: parse 429 Retry-After and respect backoff deadlines.

## Why

Ignoring Retry-After keeps you rate limited for longer.

## A bad example

```ts
if (res.status === 429) return call();
```

## A good example

```ts
if (res.status === 429) await sleep(retryAfterMs(res));
```

## How to silence it

A person can silence one finding with `brevio-core: ignore R10.3 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
