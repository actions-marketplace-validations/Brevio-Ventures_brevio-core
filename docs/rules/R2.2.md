# R2.2: Tenant-scoped data access

**Short answer:** A DB read or write filters by the authenticated workspace scope. One query without the tenant filter leaks every tenant's rows.

Group: Security and tenancy. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Tenant-scoped data access: a DB read or write filters by the authenticated workspace scope.

## Why

One query without the tenant filter leaks every tenant's rows.

## A bad example

```ts
db.select().from(orders).where(eq(orders.id, id))
```

## A good example

```ts
db.select().from(orders).where(and(eq(orders.id, id), eq(orders.tenantId, session.tenantId)))
```

## How to silence it

A person can silence one finding with `brevio-core: ignore R2.2 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

What the scanner already leaves alone: Only API code under apps/api/ is checked, and only a filter the change removes.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
