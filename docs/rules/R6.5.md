# R6.5: Post-incident regression crystallization

**Short answer:** A bug fix comes with a failing-first test. A bug without a test comes back.

Group: Testing and hermeticity. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Post-incident regression crystallization: a bug fix comes with a failing-first test.

## Why

A bug without a test comes back.

## A bad example

```
fix: handle empty cart   (no test)
```

## A good example

```
fix: handle empty cart   (adds a test that fails without the fix)
```

## How it is checked

- Nothing yet. No `brevio-core` command checks it and no `brief` reminder names it: it is a standing rule for authors and reviewers.
- Test-custody findings now print as R20.x. The findings about a deleted, renamed, weakened or skipped test, printed as R6.5 up to 0.9.1, are R20.1 to R20.4; see [R20.1](R20.1.md).

## Measured precision

Not measured. No judged sample of this rule's hits exists.

## How to silence it

A person can silence one finding with `brevio-core: ignore R6.5 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
