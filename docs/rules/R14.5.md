# R14.5: No credentials in URLs

**Short answer:** Pass tokens, API keys and passwords outside query strings. Anything in a URL ends up in logs, history and referrer headers.

Group: Auth and sessions. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

No credentials in URLs: pass tokens, API keys and passwords outside query strings.

## Why

Anything in a URL ends up in logs, history and referrer headers.

## A bad example

```ts
fetch(`/api?token=${token}`)
```

## A good example

```ts
fetch('/api', { headers: { Authorization: `Bearer ${token}` } })
```

## How to silence it

A person can silence one finding with `brevio-core: ignore R14.5 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
