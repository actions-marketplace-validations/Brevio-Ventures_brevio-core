# R20.4: No tautological assertion added

**Short answer:** Assert real output or state. An assertion that compares a value with itself, or asserts True, passes whatever the code does.

Group: Test custody. Status: preview. New, and not measured on any code yet. A finding is a prompt for a reviewer, not proof of a problem: a change can drop or rewrite a test for a good reason. `brevio-core scan` does not run this rule, so no scan fails on it. `brevio-core check` reports it and exits 1 when it does. Generated from the rule definitions; do not edit by hand.

## What it catches

No tautological assertion added: assert real output or state.

## Why

An assertion that compares a value with itself, or asserts True, passes whatever the code does.

## A bad example

```
expect(result).toBe(result);
```

## A good example

```
// assert the real value:
expect(result).toBe(30);
```

## How it is checked

- `brevio-core check` reads the lines the change adds. The agent hook runs it when the agent stops, and `brevio-core patch` runs it on an edit before writing it. `brevio-core scan` does not run it.

## Measured precision

Not measured. No judged sample of this rule's hits exists.

## How to silence it

An ignore comment does not silence this rule: `brevio-core check` does not read one for it, and a setting in `brevio-core.toml` does not turn it off. A person who means the change keeps it for a reviewer to accept; an agent restores the test.

What the check already leaves alone: comment lines are not flagged.

To change what the rule flags, edit its check in `gates/core_gates.py`. That is a code change and is reviewed like one.
