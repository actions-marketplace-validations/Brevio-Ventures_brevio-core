# R18.3: Keyboard navigation accessibility

**Short answer:** Interactive elements focusable via Tab and Enter/Space. If a control cannot be reached with the keyboard, some people cannot use it.

Group: Accessibility (WCAG 2.1 AA). Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Keyboard navigation accessibility: interactive elements focusable via Tab and Enter/Space.

## Why

If a control cannot be reached with the keyboard, some people cannot use it.

## A bad example

```tsx
<div onClick={open}>Open</div>
```

## A good example

```tsx
<button onClick={open}>Open</button>
```

## How to silence it

A person can silence one finding with `brevio-core: ignore R18.3 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
