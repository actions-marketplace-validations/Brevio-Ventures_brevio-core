# R5.3: Bounded retry with jitter

**Short answer:** Retry only transient 429/502/503/504 with backoff + jitter. Retrying every error, at once, turns one outage into many.

Group: Reliability and fallbacks. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Bounded retry with jitter: retry only transient 429/502/503/504 with backoff + jitter.

## Why

Retrying every error, at once, turns one outage into many.

## A bad example

```ts
while (true) { try { return await call(); } catch {} }
```

## A good example

```ts
retry(call, { on: [429, 502, 503, 504], backoff: 'exponential', jitter: true })
```

## How to silence it

A person can silence one finding with `brevio-core: ignore R5.3 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
