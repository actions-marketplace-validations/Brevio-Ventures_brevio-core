# R5.1: Deterministic graceful fallbacks

**Short answer:** Return an explicit degraded status, not fabricated metrics. A made-up number looks real on a dashboard and drives wrong decisions.

Group: Reliability and fallbacks. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Deterministic graceful fallbacks: return an explicit degraded status, not fabricated metrics.

## Why

A made-up number looks real on a dashboard and drives wrong decisions.

## A bad example

```ts
return { revenue: lastKnown ?? 0 };
```

## A good example

```ts
return { status: 'degraded', revenue: null };
```

## How it is checked

- `brevio-core brief` and the `brief` tool of `brevio-core mcp` print a one-line reminder of it for a file that matches.

## Measured precision

Not measured. No judged sample of this rule's hits exists.

## How to silence it

A person can silence one finding with `brevio-core: ignore R5.1 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
