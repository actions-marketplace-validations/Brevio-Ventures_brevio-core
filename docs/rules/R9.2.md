# R9.2: No silenced type errors

**Short answer:** @ts-ignore is flagged; use @ts-expect-error and say why. A silenced error hides a real bug, and nobody remembers why.

Group: Type safety. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

No silenced type errors: @ts-ignore is flagged; use @ts-expect-error and say why.

## Why

A silenced error hides a real bug, and nobody remembers why.

## A bad example

```ts
// @ts-ignore
const a = b.c;
```

## A good example

```ts
// @ts-expect-error -- the library types omit this field
const a = b.c;
```

## How it is checked

- What it reads: JavaScript and TypeScript: @ts-ignore. The reason after @ts-expect-error is not checked.
- `brevio-core scan` checks the lines you add for it.
- `brevio-core brief` and the `brief` tool of `brevio-core mcp` print a one-line reminder of it for a file that matches.

## Measured precision

100% of 20 judged hits were real, on human-written code, one reviewer (corpus ts-react-oss, run on 2026-11-06). That is not how often the rule is right on code an agent wrote. See `docs/precision.md` in the brevio-core repository for the verdicts, the commands to run it again and how to dispute one.

## How to silence it

A person can silence one finding with `brevio-core: ignore R9.2 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

A scan reads only the lines you add, so a line that was already in the file is not flagged.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
