# R9.3: Package-name imports

**Short answer:** Import workspace packages by name, not via ../../packages/ paths. A path that climbs into packages/ skips the package's exports map and build boundary.

Group: Type safety. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Package-name imports: import workspace packages by name, not via ../../packages/ paths.

## Why

A path that climbs into packages/ skips the package's exports map and build boundary.

## A bad example

```ts
import { Button } from '../../packages/ui/button';
```

## A good example

```ts
import { Button } from '@acme/ui';
```

## How it is checked

- `brevio-core scan --surface` checks the lines you add for it; a plain `brevio-core scan` does not.
- `brevio-core brief` and the `brief` tool of `brevio-core mcp` print a one-line reminder of it for a file that matches.

## Measured precision

Not measured. No judged sample of this rule's hits exists.

## How to silence it

A person can silence one finding with `brevio-core: ignore R9.3 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

What the scanner already leaves alone: Comment lines are not flagged.

A scan reads only the lines you add, so a line that was already in the file is not flagged.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
