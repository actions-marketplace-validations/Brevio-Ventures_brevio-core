# R16.2: No wildcard dependency versions

**Short answer:** Package.json does not use '*' or 'latest'. A wildcard version takes whatever was published last, including a bad release.

Group: Supply chain. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

No wildcard dependency versions: package.json does not use '*' or 'latest'.

## Why

A wildcard version takes whatever was published last, including a bad release.

## A bad example

```json
"left-pad": "*"
```

## A good example

```json
"left-pad": "1.3.0"
```

## How it is checked

- What it reads: package.json, with one key per line or several on a minified line.
- `brevio-core scan` checks the lines you add for it.

## Measured precision

Not measured. No judged sample of this rule's hits exists.

## How to silence it

A person can silence one finding with `brevio-core: ignore R16.2 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

What the scanner already leaves alone: Only package.json is checked, and the top-level version and private fields are not flagged.

A scan reads only the lines you add, so a line that was already in the file is not flagged.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
