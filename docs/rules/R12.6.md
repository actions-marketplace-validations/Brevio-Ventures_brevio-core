# R12.6: Worker thread termination

**Short answer:** Spawn worker instances call terminate() upon task completion. A worker that is never terminated keeps a thread and its memory.

Group: Memory and resource leaks. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Worker thread termination: spawn worker instances call terminate() upon task completion.

## Why

A worker that is never terminated keeps a thread and its memory.

## A bad example

```ts
const w = new Worker(file);
```

## A good example

```ts
const w = new Worker(file);
w.on('message', done).on('message', () => w.terminate());
```

## How to silence it

A person can silence one finding with `brevio-core: ignore R12.6 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.
