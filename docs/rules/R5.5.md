# R5.5: Process safety

**Short answer:** No subprocess call with shell=True and no os.system call built from an f-string. Passing shell=True or an interpolated command string runs a shell that can execute injected input.

Group: Reliability and fallbacks. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Process safety: no subprocess call with shell=True and no os.system call built from an f-string.

## Why

Passing shell=True or an interpolated command string runs a shell that can execute injected input.

## A bad example

```py
subprocess.run(cmd, shell=True)
```

## A good example

```py
subprocess.run(cmd, timeout=60, check=True)
```

## How it is checked

- What it reads: Python only.
- `brevio-core scan` checks the lines you add for it.

## How to silence it

A person can silence one finding with `brevio-core: ignore R5.5 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

What the scanner already leaves alone: Test files and comment lines are not flagged.

A scan reads only the lines you add, so a line that was already in the file is not flagged.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
