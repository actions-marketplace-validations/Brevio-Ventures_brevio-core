# R19.3: No dead commented-out code

**Short answer:** Remove obsolete commented code blocks prior to PR merge. Commented-out code goes stale, and git already keeps the old version.

Group: Clean code. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

No dead commented-out code: remove obsolete commented code blocks prior to PR merge.

## Why

Commented-out code goes stale, and git already keeps the old version.

## A bad example

```py
# old_call(x)
new_call(x)
```

## A good example

```py
new_call(x)
```

## How it is checked

- Nothing yet. No `brevio-core` command checks it and no `brief` reminder names it: it is a standing rule for authors and reviewers.

## How to silence it

A person can silence one finding with `brevio-core: ignore R19.3 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
