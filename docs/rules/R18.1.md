# R18.1: Image alternative text

**Short answer:** Img elements carry an alt attribute. A screen reader reads nothing for an image with no alt text.

Group: Accessibility (WCAG 2.1 AA). Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Image alternative text: img elements carry an alt attribute.

## Why

A screen reader reads nothing for an image with no alt text.

## A bad example

```tsx
<img src="/logo.png" />
```

## A good example

```tsx
<img src="/logo.png" alt="Acme logo" />
```

## How it is checked

- `brevio-core scan` checks the lines you add for it.

88% of 8 judged hits were real, on human-written code, one reviewer (corpus ts-react-oss, run on 2026-11-06). That is not how often the rule is right on code an agent wrote. See `docs/precision.md` in the brevio-core repository for the verdicts, the commands to run it again and how to dispute one.

## How to silence it

A person can silence one finding with `brevio-core: ignore R18.1 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

What the scanner already leaves alone: Only <img> tags written on a single added line are checked.

A scan reads only the lines you add, so a line that was already in the file is not flagged.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
