# R10.1: Explicit HTTP request timeouts

**Short answer:** Python requests calls pass timeout=. A request with no timeout can hang a worker for ever.

Group: API and network robustness. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Explicit HTTP request timeouts: Python requests calls pass timeout=.

## Why

A request with no timeout can hang a worker for ever.

## A bad example

```py
response = requests.get(url)
```

## A good example

```py
response = requests.get(url, timeout=10)
```

## How it is checked

- What it reads: Python only: calls of requests.get, post, put, delete, patch and head. Not httpx, not fetch and not axios; R10.9 covers fetch and axios.
- `brevio-core scan` checks the lines you add for it.

## Measured precision

Not measured. No judged sample of this rule's hits exists.

## How to silence it

A person can silence one finding with `brevio-core: ignore R10.1 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

What the scanner already leaves alone: Test files and calls that pass timeout= on the same line are not flagged.

A scan reads only the lines you add, so a line that was already in the file is not flagged.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
