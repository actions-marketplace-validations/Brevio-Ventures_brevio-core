# R18.2: Form control labels

**Short answer:** Input, select and textarea elements have a label (not scanned); the scan checks target="_blank" links for rel="noopener noreferrer". A target="_blank" link without rel="noopener noreferrer" exposes the opener window to the linked page.

Group: Accessibility (WCAG 2.1 AA). Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Form control labels: input, select and textarea elements have a label (not scanned); the scan checks target="_blank" links for rel="noopener noreferrer".

## Why

A target="_blank" link without rel="noopener noreferrer" exposes the opener window to the linked page.

## A bad example

```tsx
<a href="/docs" target="_blank">Docs</a>
```

## A good example

```tsx
<a href="/docs" target="_blank" rel="noopener noreferrer">Docs</a>
```

## How it is checked

- `brevio-core scan` checks the lines you add for it.

Not measured. No judged sample of this rule's hits exists.

## How to silence it

A person can silence one finding with `brevio-core: ignore R18.2 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

What the scanner already leaves alone: Test files and links that include noopener in rel= on the same tag are not flagged.

A scan reads only the lines you add, so a line that was already in the file is not flagged.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
