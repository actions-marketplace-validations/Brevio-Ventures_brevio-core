# R5.2: HTTP empty-body hygiene

**Short answer:** 204 returns empty body; 200 JSON sets Content-Type. A 204 with a body, or JSON without a Content-Type, breaks clients and proxies.

Group: Reliability and fallbacks. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

HTTP empty-body hygiene: 204 returns empty body; 200 JSON sets Content-Type.

## Why

A 204 with a body, or JSON without a Content-Type, breaks clients and proxies.

## A bad example

```ts
return new Response('ok', { status: 204 });
```

## A good example

```ts
return new Response(null, { status: 204 });
```

## How it is checked

- `brevio-core brief` and the `brief` tool of `brevio-core mcp` print a one-line reminder of it for a file that matches.

Not measured. No judged sample of this rule's hits exists.

## How to silence it

A person can silence one finding with `brevio-core: ignore R5.2 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
