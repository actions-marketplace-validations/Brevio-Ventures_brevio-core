# R20.3: No test skip or focus marker added

**Short answer:** Fix the failing test instead of silencing it. A skipped or focused test stops running, or stops the others, while the build stays green. The failure it hides is still there.

A finding is a prompt for a reviewer, not proof of a problem: a change can drop or rewrite a test for a good reason. `brevio-core scan` does not run this rule, so no scan fails on it. `brevio-core check` reports it and exits 1 when it does. ## What it catches

No test skip or focus marker added: fix the failing test instead of silencing it.

## Why

A skipped or focused test stops running, or stops the others, while the build stays green. The failure it hides is still there.

## A bad example

```
it.skip('charges the card', () => { chargeCard(); });
```

## A good example

```
// fix the code or the test, and keep it running:
it('charges the card', () => { chargeCard(); });
```

## How it is checked

- `brevio-core check` reads the lines the change adds. The agent hook runs it when the agent stops, and `brevio-core patch` runs it on an edit before writing it. `brevio-core scan` does not run it.

## How to silence it

An ignore comment does not silence this rule: `brevio-core check` does not read one for it, and a setting in `brevio-core.toml` does not turn it off. A person who means the change keeps it for a reviewer to accept; an agent restores the test.

What the check already leaves alone: comment lines are not flagged, and the markers it reads are `it`, `test` and `describe` with `.skip` or `.only`, `xit`, `xtest`, `xdescribe`, and the pytest and unittest skip decorators.

To change what the rule flags, edit its check in `gates/core_gates.py`. That is a code change and is reviewed like one.
