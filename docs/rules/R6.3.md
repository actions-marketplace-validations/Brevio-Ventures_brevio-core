# R6.3: No fixed-length waitForTimeout in tests

**Short answer:** Wait for a condition instead. A sleep is either too short (flaky) or too long (slow).

Group: Testing and hermeticity. Status: preview. In a precision run on open-source repositories most of its hits were deliberate waits (a test checking that nothing happens in a given time) or test code written as a string, so it reports but never fails a scan until it can tell those from a sleep that stands in for a condition. Generated from the rule definitions; do not edit by hand.

## What it catches

No fixed-length waitForTimeout in tests: wait for a condition instead.

## Why

A sleep is either too short (flaky) or too long (slow).

## A bad example

```ts
await page.waitForTimeout(2000);
```

## A good example

```ts
await expect(page.getByText('Saved')).toBeVisible();
```

## How it is checked

- What it reads: A test file in any language: waitForTimeout with a number. A sleep call is not checked.
- `brevio-core scan` checks the lines you add for it.
- `brevio-core brief` and the `brief` tool of `brevio-core mcp` print a one-line reminder of it for a file that matches.

## Measured precision

30% of 20 judged hits were real, on human-written code, one reviewer (corpus ts-react-oss, run on 2026-11-06). That is not how often the rule is right on code an agent wrote. See `docs/precision.md` in the brevio-core repository for the verdicts, the commands to run it again and how to dispute one.

## How to silence it

A person can silence one finding with `brevio-core: ignore R6.3 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

What the scanner already leaves alone: Only added lines in a test file are checked: a path with a folder or file name that starts or ends with the word test, tests, spec, specs, e2e or testing.

A scan reads only the lines you add, so a line that was already in the file is not flagged.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
