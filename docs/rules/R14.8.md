# R14.8: Role-based access control

**Short answer:** Enforce authorization check at controller/handler boundary. A check that lives only in the UI is skipped by anyone who calls the API.

Group: Auth and sessions. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Role-based access control: enforce authorization check at controller/handler boundary.

## Why

A check that lives only in the UI is skipped by anyone who calls the API.

## A bad example

```ts
app.delete('/users/:id', removeUser);
```

## A good example

```ts
app.delete('/users/:id', requireRole('admin'), removeUser);
```

## How to silence it

A person can silence one finding with `brevio-core: ignore R14.8 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
