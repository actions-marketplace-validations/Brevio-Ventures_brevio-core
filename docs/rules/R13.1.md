# R13.1: No hardcoded secrets

**Short answer:** Credentials stay out of source code and out of browser bundles. A secret written into code is copied wherever the code goes: clones, builds and logs.

Group: Observability and logging. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

No hardcoded secrets: credentials stay out of source code and out of browser bundles.

## Why

A secret written into code is copied wherever the code goes: clones, builds and logs.

## A bad example

```ts
const sessionToken = 'eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIxMjM0In0.example-signature';
```

## A good example

```ts
const sessionToken = process.env.SESSION_TOKEN;
```

## How it is checked

- What it reads: Code files outside tests. Where a secret is logged is not checked.
- `brevio-core scan` checks the lines you add for it.

## Measured precision

Not measured: the rule had no hit in the corpus (corpus ts-react-oss, run on 2026-11-06), so there was nothing to judge.

## How to silence it

A person can silence one finding with `brevio-core: ignore R13.1 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

What the scanner already leaves alone: Only a known credential format (AWS, GitHub, Slack, Stripe live, Google API key, a private key block) or a random-looking value bound to a secret, token, password or API key name is flagged; a JWT bound to such a name always is. Test files are not checked. A placeholder (example, fake, test, xxxx, your-...) is not a key. Keys that are public by design are not flagged: a name that says public or publishable, a Stripe pk_ key, and an Algolia or DocSearch key (named so, or in the five lines below such a name). A secret-named NEXT_PUBLIC_, VITE_ or REACT_APP_ variable is flagged with its own message: the build copies it into the browser bundle, so a secret does not belong in it.

A scan reads only the lines you add, so a line that was already in the file is not flagged.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
