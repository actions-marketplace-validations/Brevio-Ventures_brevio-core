# R20.2: Existing tests and assertions kept

**Short answer:** A changed test file does not hold fewer tests or assertions than its base. A test file with fewer tests or assertions than before checks less. The count is a plain count of test functions and assertion calls in the file, so a test moved to another file reads as fewer too.

## What it catches

Existing tests and assertions kept: a changed test file does not hold fewer tests or assertions than its base.

## Why

A test file with fewer tests or assertions than before checks less. The count is a plain count of test functions and assertion calls in the file, so a test moved to another file reads as fewer too.

## A bad example

```
def test_total():
    assert total(cart) == 30   # the second assertion was dropped
```

## A good example

```
keep the assertions the file had:
def test_total():
    assert total(cart) == 30
    assert total([]) == 0
```

## How it is checked

- `brevio-core check` compares the working tree with `--base` (default `HEAD`). The agent hook runs the same comparison when the agent stops, and `brevio-core patch` runs it on an edit before writing it. `brevio-core scan` does not run it.

## How to silence it

An ignore comment does not silence this rule: `brevio-core check` does not read one for it, and a setting in `brevio-core.toml` does not turn it off. A person who means the change keeps it for a reviewer to accept; an agent restores the test.

What the check already leaves alone: comment lines are not counted.

To change what the rule flags, edit its check in `gates/core_gates.py`. That is a code change and is reviewed like one.
