# R9.1: No untyped escape hatches

**Short answer:** No `as any` casts or `z.any()` schemas in production source. `any` turns the type checker off for everything it touches.

Group: Type safety. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

No untyped escape hatches: no `as any` casts or `z.any()` schemas in production source.

## Why

`any` turns the type checker off for everything it touches.

## A bad example

```ts
const user = (await res.json()) as any;
```

## A good example

```ts
const user = UserSchema.parse(await res.json());
```

## How it is checked

- `brevio-core scan` checks the lines you add for it.
- `brevio-core brief` and the `brief` tool of `brevio-core mcp` print a one-line reminder of it for a file that matches.

## Measured precision

100% of 20 judged hits were real, on human-written code, one reviewer (corpus ts-react-oss, run on 2026-11-06). That is not how often the rule is right on code an agent wrote. See `docs/precision.md` in the brevio-core repository for the verdicts, the commands to run it again and how to dispute one.

## How to silence it

A person can silence one finding with `brevio-core: ignore R9.1 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

What the scanner already leaves alone: Test files, test helpers and setup files, and comment lines are not flagged.

A scan reads only the lines you add, so a line that was already in the file is not flagged.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
