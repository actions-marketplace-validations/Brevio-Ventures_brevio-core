# R2.5: Outbound SSRF & timeout guard

**Short answer:** Validate URL host and set AbortSignal.timeout(). A server that fetches any URL can be pointed at your internal network, and a call with no limit can hang.

Group: Security and tenancy. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Outbound SSRF & timeout guard: validate URL host and set AbortSignal.timeout().

## Why

A server that fetches any URL can be pointed at your internal network, and a call with no limit can hang.

## A bad example

```ts
const res = await fetch(req.query.url);
```

## A good example

```ts
const url = new URL(input);
if (!ALLOWED.has(url.host)) throw new Error('host');
await fetch(url, { signal: AbortSignal.timeout(5000) });
```

## How to silence it

A person can silence one finding with `brevio-core: ignore R2.5 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
