# R14.3: Token expiration bounding

**Short answer:** Short-lived access tokens paired with rotating refresh tokens. A long-lived token that leaks stays useful for months.

Group: Auth and sessions. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Token expiration bounding: short-lived access tokens paired with rotating refresh tokens.

## Why

A long-lived token that leaks stays useful for months.

## A bad example

```ts
sign(payload, key, { expiresIn: '365d' })
```

## A good example

```ts
sign(payload, key, { expiresIn: '15m' })  // plus a rotating refresh token
```
