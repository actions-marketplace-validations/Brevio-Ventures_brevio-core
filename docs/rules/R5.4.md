# R5.4: No silent exception swallowing

**Short answer:** Log or surface errors; empty catch blocks, bare except and except Exception: pass are flagged. An error that is swallowed leaves no trace, so a failure looks like success.

Group: Reliability and fallbacks. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

No silent exception swallowing: log or surface errors; empty catch blocks, bare except and except Exception: pass are flagged.

## Why

An error that is swallowed leaves no trace, so a failure looks like success.

## A bad example

```ts
try { await save(); } catch (e) {}
```

## A good example

```ts
try { await save(); } catch (e) { log.error('save failed', e); throw e; }
```

The fix depends on the finding and the language:

- a bare except in Python: `except ValueError as exc:  # name the error, then log it or raise again`
- an empty catch in TypeScript and JavaScript: `try { await save(); } catch (e) { log.error('save failed', e); throw e; }`

## How it is checked

- What it reads: JavaScript and TypeScript: an empty catch block. Python: a bare except that does not re-raise, and an except handler for Exception whose body is only pass or `...`. A handler that names a narrower error, such as OSError, is not flagged.
- `brevio-core scan` checks the lines you add for it.
- `brevio-core brief` and the `brief` tool of `brevio-core mcp` print a one-line reminder of it for a file that matches.

## Measured precision

75% of 20 judged hits were real, on human-written code, one reviewer (corpus ts-react-oss, run on 2026-11-06). That is not how often the rule is right on code an agent wrote. See `docs/precision.md` in the brevio-core repository for the verdicts, the commands to run it again and how to dispute one. The Python checks of this rule were added after this run, so they are not measured.

## How to silence it

A person can silence one finding with `brevio-core: ignore R5.4 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

What the scanner already leaves alone: A bare `except:` whose handler re-raises with a plain `raise` at its top level is not flagged; a `raise` inside an `if`, or `raise SomethingElse`, does not count.

A scan reads only the lines you add, so a line that was already in the file is not flagged.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
