# R10.9: Timeouts on fetch and axios

**Short answer:** A call with no options argument sets no timeout and no AbortSignal. A fetch with no options has no way to stop waiting, so a slow server holds the request, and the user, for as long as it likes.

Group: API and network robustness. Status: preview. New, and not measured on any code yet. It reads one line and flags only a call that has no options argument at all, which cannot carry a signal or a timeout. It reports but never fails a scan until a precision run judges it. Generated from the rule definitions; do not edit by hand.

## What it catches

Timeouts on fetch and axios: a call with no options argument sets no timeout and no AbortSignal.

## Why

A fetch with no options has no way to stop waiting, so a slow server holds the request, and the user, for as long as it likes.

## A bad example

```ts
const res = await fetch(url);
```

## A good example

```ts
const res = await fetch(url, { signal: AbortSignal.timeout(10_000) });
```

## How it is checked

- What it reads: JavaScript and TypeScript, outside test files: fetch and axios calls. Python is not read.
- `brevio-core scan` checks the lines you add for it.

## Measured precision

Not measured. No judged sample of this rule's hits exists.

## How to silence it

A person can silence one finding with `brevio-core: ignore R10.9 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

What the scanner already leaves alone: A line that names signal or timeout, a call that has an options argument, a call that does not close on the line, and test files are not flagged. A timeout set once on an axios instance or in axios.defaults is not seen, so a call that relies on it is flagged.

A scan reads only the lines you add, so a line that was already in the file is not flagged.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
