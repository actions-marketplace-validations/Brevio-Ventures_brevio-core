# R6.2: Mutation side-effect assertions

**Short answer:** Assert persisted state or DOM changes, not just HTTP 200. A test that only checks a value exists passes when the behaviour is wrong.

Group: Testing and hermeticity. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Mutation side-effect assertions: assert persisted state or DOM changes, not just HTTP 200.

## Why

A test that only checks a value exists passes when the behaviour is wrong.

## A bad example

```ts
expect(result).toBeDefined();
expect(row).toBeTruthy();
```

## A good example

```ts
expect(res.status).toBe(200);
expect(row.name).toBe('Ada');
```

## How it is checked

- `brevio-core scan --surface` checks the lines you add for it; a plain `brevio-core scan` does not.
- `brevio-core brief` and the `brief` tool of `brevio-core mcp` print a one-line reminder of it for a file that matches.

## Measured precision

Not measured. No judged sample of this rule's hits exists.

## How to silence it

A person can silence one finding with `brevio-core: ignore R6.2 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

A scan reads only the lines you add, so a line that was already in the file is not flagged.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
