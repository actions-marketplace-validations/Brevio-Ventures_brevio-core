# R4.1: Expand-contract migrations

**Short answer:** Additive nullable/default columns; no single-step drop/rename. A one-step drop breaks the old code that is still running during the deploy.

Group: Database and migrations. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Expand-contract migrations: additive nullable/default columns; no single-step drop/rename.

## Why

A one-step drop breaks the old code that is still running during the deploy.

## A bad example

```sql
ALTER TABLE users DROP COLUMN name;
```

## A good example

```sql
ALTER TABLE users ADD COLUMN full_name text NULL;  -- drop 'name' in a later release
```

## How to silence it

A person can silence one finding with `brevio-core: ignore R4.1 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.

To change what the rule flags, edit its check in the rule code of the package. That is a code change and is reviewed like one.
