# R11.1: Atomic read-modify-write

**Short answer:** Concurrent mutations use compare-and-swap or row locks. Two writers that read, change and write lose one of the changes.

Group: State and concurrency. Status: stable. Generated from the rule definitions; do not edit by hand.

## What it catches

Atomic read-modify-write: concurrent mutations use compare-and-swap or row locks.

## Why

Two writers that read, change and write lose one of the changes.

## A bad example

```ts
const n = await get(); await set(n + 1);
```

## A good example

```ts
await db.update({ where: { id, version }, data: { n: n + 1, version: version + 1 } });
```

## How to silence it

A person can silence one finding with `brevio-core: ignore R11.1 -- reason` on the line or the line above. Without the reason it does not count. An agent cannot silence it: the agent hook and the MCP tools never honour the comment, and a pull request that adds one is reported until a reviewer allows it. Fixing the code is still the better answer.
